# Prompt · Build a first-order codebook

> ⚠️ **Transcripts are participant data under IRB-25-0462.** Do not paste raw
> transcripts into a general-purpose chat interface. Use de-identified excerpts,
> or run this in an approved environment. If in doubt, do not run it.

Self-contained. Paste the whole file, then the excerpt.

```
INPUTS
  EXCERPT:        <de-identified transcript text>
  EXISTING_CODES: <the current codebook, or "none — first pass">
  RQ:             <the research question, so codes stay anchored to it>

OUTPUTS
  A first-order code table, a comparison note, and a list of what did not fit.
```

---

Produce **first-order codes only**. First-order means the participant's own
words and categories. Do not interpret, do not theorise, do not group into
themes. That is a separate pass and mixing them destroys the audit trail.

**1. Code table:**

| Code (informant's language) | Supporting quote | Line ref |

Rules:
- The code label uses the participant's vocabulary, not research vocabulary. If
  you find yourself writing *anchoring*, *bias* or *reliance*, you have crossed
  into second-order. Stop and relabel.
- Every code carries a verbatim quote. A code without a quote is an impression.
- One code per distinct idea. Do not merge for tidiness.

**2. Constant comparison** — against EXISTING_CODES, state:
- which existing codes this excerpt **confirms**
- which it **strains** — the code still holds but the boundary is now unclear
- which it **contradicts**
- which codes are **new**

If EXISTING_CODES is "none", say so and skip.

**3. Did not fit** — anything in the excerpt that is clearly meaningful but does
not fall under any code, existing or new. Quote it and leave it uncoded.

This last list is the most valuable output. It is where the next category comes
from, and a codebook that never produces one is being applied rather than built.

Do not propose themes. Do not suggest what the data means.
