# Career documents

## Method
1. Match the target role and employer language without keyword stuffing.
2. Lead with scope, outcomes and evidence; quantify only what is supported.
3. Separate technical capability, governance/risk depth and leadership impact.
4. Remove generic adjectives that are not evidenced by accomplishment.
5. Keep ATS-safe structure for resumes while using `brand-design` for polished visual versions.
6. Never invent employers, titles, dates, degrees, certifications, metrics or tool experience.
7. Keep private contact details out of public Git unless the user explicitly approves publication.

## Quality gate
- Every claim is supportable.
- First third of the document communicates role fit immediately.
- Repetition is removed.
- Formatting is readable in PDF and plain-text extraction.
- Public versions contain only approved contact information.
